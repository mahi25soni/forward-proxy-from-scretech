HTTP Server in C

Same HTTP server, three ways to wait on connections: threads, select, and epoll. This page is served from public/ — if you see styling and the status below, static file routing works.

HTML CSS JS
v1 · macOS & Linux

Threads

One pthread per connection. First step after sockets.

  • Syscalls and error handling — not fetch()
  • malloc, pointers, memory you own
  • Threads block on read() — costly at scale
v2 · macOS & Linux

select

Single-threaded I/O multiplexing.

  • One thread, many connections
  • Wait until the kernel says a fd is readable
  • Multiplexing fixes waiting, not heavy CPU work
v3 · Linux only

epoll

Kernel keeps interest; epoll_wait returns ready fds.

  • No rebuilding the full fd set every loop
  • epoll_event.data — opaque payload you define
  • Not on macOS — use Docker or v1/v2 locally

How this request works

Connection = one TCP socket. Request = one GET /path. Your browser may open one connection and send several requests (HTML, CSS, JS) — or open new ones. That behavior depends on which server binary you started and keep-alive headers.
